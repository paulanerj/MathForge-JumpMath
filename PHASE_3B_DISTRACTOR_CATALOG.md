## 1. Overview of Pedagogical Distractor Architecture

In traditional digital game math, distractors (wrong answers) are frequently generated by adding arbitrary random integers ($\pm \text{rand}(1, 5)$). This produces low-quality decoys that fail to challenge the learner or provide meaningful diagnostic insight into learner misunderstandings.

In ZYX Phase 3B, the `DistractorPipeline` introduces **Intentional Pedagogical Error Models**. Every distractor offered to the learner models a documented arithmetic misconception or procedural slip. 

When a learner chooses a decoy platform:
1. The error reflects a known cognitive slip.
2. The specific `errorModel` tag is recorded in `MathAnswerOption`, `Platform`, and `MathChallengeResult`.
3. The platform engine can emit rich diagnostic learner evidence for educational telemetry and adaptive intervention.

## 2. Comprehensive Error Model Catalog

### 2.1 `OFF_BY_ONE`
* **Error Model ID:** `OFF_BY_ONE`
* **Misconception:** Standard counting slip or fencepost error. The learner begins counting from the wrong anchor or counts one too many/few ticks.
* **Applicable Modes:** `SKIP_COUNT`, `SUM_TO`
* **Mathematical Formula:**
  $$v = \text{correctAnswer} \pm 1$$
* **Examples:**
  * *Skip Counting (+5 from 20):* Correct = 25. Decoys = 26 or 24.
  * *Sum To (Target 10, Current 4):* Correct = 6. Decoys = 7 or 5.

---

### 2.2 `OVER_SKIP`
* **Error Model ID:** `OVER_SKIP`
* **Misconception:** Double-hop or overshooting. The learner applies the step twice instead of once, often due to impatience or misjudging a rhythmic leap.
* **Applicable Modes:** `SKIP_COUNT`
* **Mathematical Formula:**
  $$v = \text{correctAnswer} + (\text{direction} \times \text{step})$$
* **Examples:**
  * *Forward (+3 from 9):* Correct = 12. Decoy = $12 + 3 = 15$.
  * *Backward (-5 from 30):* Correct = 25. Decoy = $25 - 5 = 20$.

---

### 2.3 `UNDER_SKIP`
* **Error Model ID:** `UNDER_SKIP`
* **Misconception:** Incomplete hop or stopping short. The learner increments by less than the full step (e.g., half-step or step minus one).
* **Applicable Modes:** `SKIP_COUNT` (for $\text{step} > 1$)
* **Mathematical Formulas:**
  $$v_1 = \text{correctAnswer} - (\text{direction} \times \max(1, \lfloor\text{step}/2\rfloor))$$
  $$v_2 = \text{currentVal} + (\text{direction} \times (\text{step} - 1))$$
* **Examples:**
  * *Forward (+6 from 12):* Correct = 18. Decoys = $18 - 3 = 15$ or $12 + 5 = 17$.
  * *Backward (-10 from 50):* Correct = 40. Decoys = $40 + 5 = 45$.

---

### 2.4 `WRONG_DIRECTION`
* **Error Model ID:** `WRONG_DIRECTION`
* **Misconception:** Sign reversal. In a descending countdown, the learner adds the step instead of subtracting; in an ascending sequence, the learner subtracts.
* **Applicable Modes:** `SKIP_COUNT`
* **Mathematical Formula:**
  $$v = \text{currentVal} - (\text{direction} \times \text{step})$$
* **Examples:**
  * *Backward (-5 from 25):* Correct = 20. Decoy = $25 + 5 = 30$.
  * *Forward (+4 from 16):* Correct = 20. Decoy = $16 - 4 = 12$.

---

### 2.5 `PREVIOUS_TERM`
* **Error Model ID:** `PREVIOUS_TERM`
* **Misconception:** Zero progression / inertia. The learner repeats the number currently displayed on the character's platform without performing the required operation.
* **Applicable Modes:** `SKIP_COUNT`, `SUM_TO`
* **Mathematical Formula:**
  $$v = \text{currentVal}$$
* **Examples:**
  * *Skip Counting (+3 from 15):* Correct = 18. Decoy = 15.
  * *Sum To (Target 12, Current 5):* Correct = 7. Decoy = 5.

---

### 2.6 `STEP_VALUE_CONFUSION`
* **Error Model ID:** `STEP_VALUE_CONFUSION`
* **Misconception:** Parameter confusion. The learner fixates on the stated step size rule (e.g., "count by 5s") and selects the step number itself rather than adding it to the current term.
* **Applicable Modes:** `SKIP_COUNT`
* **Mathematical Formula:**
  $$v = \text{step}$$
* **Examples:**
  * *Skip by 5 from 35:* Correct = 40. Decoy = 5.
  * *Skip by 3 from 21:* Correct = 24. Decoy = 3.

---

### 2.7 `TARGET_CONFUSION`
* **Error Model ID:** `TARGET_CONFUSION`
* **Misconception:** Goal fixation. In missing-addend problems ($a + ? = T$), the learner selects the target sum $T$ itself instead of calculating the missing complement.
* **Applicable Modes:** `SUM_TO`
* **Mathematical Formula:**
  $$v = \text{target}$$
* **Examples:**
  * *Sum to 10 with Current = 3:* Correct = 7. Decoy = 10.
  * *Sum to 20 with Current = 8:* Correct = 12. Decoy = 20.

---

### 2.8 `NEAR_RESULT`
* **Error Model ID:** `NEAR_RESULT`
* **Misconception:** Small arithmetic computation error. The learner miscalculates the complement by 2 units.
* **Applicable Modes:** `SUM_TO`
* **Mathematical Formula:**
  $$v = \text{correctAnswer} \pm 2$$
* **Examples:**
  * *Sum to 10 with Current = 4:* Correct = 6. Decoys = 8 or 4 (filtered if collides with current).
  * *Sum to 15 with Current = 6:* Correct = 9. Decoys = 11 or 7.

---

### 2.9 `ADD_ALL_VALUES`
* **Error Model ID:** `ADD_ALL_VALUES`
* **Misconception:** Operator misinterpretation. The learner sees two visible numbers (current value and target sum) and adds them together rather than subtracting to find the complement.
* **Applicable Modes:** `SUM_TO`
* **Mathematical Formula:**
  $$v = \text{currentVal} + \text{target}$$
* **Examples:**
  * *Sum to 10 with Current = 4:* Correct = 6. Decoy = $4 + 10 = 14$.
  * *Sum to 12 with Current = 5:* Correct = 7. Decoy = $5 + 12 = 17$.

---

### 2.10 `FALLBACK`
* **Error Model ID:** `FALLBACK`
* **Description:** Pseudo-random bounded positive integer generator used solely if all prioritized pedagogical models collide with the correct answer or existing options.
* **Empirical Rate:** **0.00%** across 15,000 challenges. The multi-candidate pipeline guarantees that pedagogical candidates completely satisfy decoy requirements under all standard bounds.

## 3. The `DistractorPipeline` Implementation (`src/math/DistractorPipeline.ts`)

The distractor generator operates as a pure, stateless functional pipeline:

```
[Candidate Error Models]
        │
        ▼
[Domain Filter] ──> Reject non-positive (or negative), null, NaN, or out-of-bounds
        │
        ▼
[Collision Filter] ──> Reject if candidate == correctAnswer or already chosen
        │
        ▼
[Shuffle & Selection] ──> Select target decoy count using injected MathRng
        │
        ▼
[Fallback Fill] ──> (Only if candidates exhausted; 0.00% in production)
        │
        ▼
[Option Assembly] ──> Attach unique option IDs and errorModel metadata
```

### Key Safety Invariants Enforced by Pipeline:
1. **Option Uniqueness:** No two options in a challenge share the same numeric value.
2. **Correct Answer Exclusivity:** Decoys cannot equal `correctAnswer`.
3. **Domain Positivity:** Values conform to `minValue` (1 by default, 0 for countdown boundary rows).
4. **Metadata Preservation:** The winning candidate's `errorModel` tag is preserved and serialized directly into `MathAnswerOption.errorModel`.
